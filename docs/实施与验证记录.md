## 一、已完成并验证的部分

### 1. 语法与编译校验

由于开发沙箱为 Linux 且无法联网获取 .NET 8 SDK，实际编译**未在本地完成**。已用可用的 .NET 6 SDK 对主程序做了降级语法编译（`net6.0` 目标），并过滤掉「缺少 Windows 专用依赖」产生的环境性报错，**未发现真实的语法或结构错误**。

校验过程中发现并修复了 2 个真实缺陷：

| 缺陷 | 位置 | 说明 |
|---|---|---|
| 静态方法名与属性名冲突 | `Core/DailyGate.cs` | `GateDecision` 同时有属性 `Proceed` 和静态方法 `Proceed()`，C# 不允许。已将工厂方法改名为 `Allow()` |
| 未释放的 `HttpClient` | `AppContextHost.cs` | `MiHoYoHttpClient` 实现了 `IDisposable` 但从未释放。已改为字段持有并在 `Dispose()` 中释放 |

另外修正了 3 处代码整洁性问题（重复的工厂方法、未使用的变量、未使用的 using）。

### 2. 核心算法交叉验证

这是本项目风险最高的部分，已用**两份独立实现互相对照**的方式验证：

### 最关键的未知项

**`act-nap-api.mihoyo.com` 接受哪套签名组合？**

这是整个项目最大的不确定性。方案里内置了三种签名模式的**自动轮换**：遇到 `retcode = -1` 时会自动从 `WebDs1 → AppDs1 → X6Ds2` 依次尝试，并把成功的模式写回配置。

所以**这个不确定性已经被代码消化掉了**，你不需要手动排查。若三种都失败，日志里会有明确记录，此时按 [接口说明](../docs/接口说明.md) 第 7 节自行抓包更新 `endpoints.json` 即可。

### 其他待确认项

- [ ] `x-rpc-channel` 是否需要（当前默认不发送；若业务报错可填 `miyousheluodi` 试试）
- [ ] `retcode = 1034` 的实际触发阈值（目前的处理是不重试）
- [ ] `WITHIN 1` 的 WMI 轮询间隔是否漏事件（若漏，改成 `WITHIN 2`）
- [ ] 长时间运行（8 小时以上）WMI 订阅是否稳定（watchdog 会每 10 分钟重建）
- [ ] 多角色签到的间隔 1200ms 是否足够（`settings.json` 的 `interRoleDelayMs` 可调）
- [ ] stoken 换 cookie_token 接口对 v2 形态 stoken 的实际表现（需要 `mid`）

## 三、开发环境说明

本项目的源码在 Linux 沙箱中编写，但：

- **无法在沙箱内编译**：目标框架 `net8.0-windows` + WinForms + WMI 均为 Windows 专属；沙箱只有 .NET 6 SDK 且无法联网安装 .NET 8
- **无法产出 Windows exe**：交叉编译 WinForms 不可行

因此交付形式为**源码 + GitHub Actions 工作流**，由 `windows-latest` 云端完成真正的编译与打包。

### 如何构建

推送到 GitHub 后：

```bash
# 方式一：自动构建（每次 push 都会跑）
git push origin main
# 到 Actions 页面下载 artifact

# 方式二：打 tag 出正式 Release
git tag v1.0.0
git push origin v1.0.0
# Actions 会创建 draft Release，含两个 zip + SHA256SUMS

# 方式三：本地 Windows 构建
dotnet publish src/ZzzAutoSign/ZzzAutoSign.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -o publish/ZzzAutoSign
```

## 四、架构决策备忘

记录几个「为什么不那样做」的决定，便于后续维护时理解。

| 决策 | 原因 |
|---|---|
| 不做账号密码自动登录 | 米哈游通行证密码登录强制极验（Geetest）行为验证码，纯 HTTP 无法通过。绕过方案要么需要把密码发送给第三方打码平台，要么需常驻自动化浏览器且容易触发风控。两者都不可接受 |
| 用 WMI 事件而非轮询 | 轮询有延迟（用户能感知到）且持续占用 CPU；WMI 事件是即时且零开销的 |
| 单文件自包含而非依赖框架 | 用户不需要预装 .NET 运行时，降低使用门槛 |
| DPAPI 而非明文配置 | Cookie 等同于登录态，明文存放风险过高。DPAPI 保证只有当前用户能解密 |
| 凭证单独存而非放 settings.json | 职责分离：`settings.json` 可以随便分享给别人看，`credential.bin` 不行 |
| 风控错误不重试 | 重试「需要验证码」这类错误只会加重风控，可能触发账号临时限制 |
| salt 做成运行时可配置 | 官方升级客户端会更换 salt，做成可配置后用户不必等新版本程序 |
| 全部成功才记录「今日完成」 | 部分角色失败时，下次启动游戏应继续尝试，不能因为一个角色成功就跳过其余角色 |
