# 排障手册

按「现象 → 原因 → 处置」查找你的问题。

---

## 快速对照表

| 现象 / 报错 | 可能原因 | 处置 |
|---|---|---|
| 完全没有通知弹出 | 系统通知被关闭 / 专注助手 | 见 [通知不弹出](#1-通知不弹出) |

| `retcode=1034` 风险校验 | 被要求验证码 | 手动签到一次 |
| `retcode=-5003` | 今日已签到 | **正常**，非错误 |
| 「该账号下没有查询到绝区零角色」 | 未绑定角色 | 在游戏内登录一次并绑定 |
| 「请求超时」/ 网络不可用 | 网络问题 | 检查网络；程序会自动重试 |
| 请求过于频繁 | 触发限流 | 程序自动退避；减少手动触发 |
| 杀毒软件报警 | 行为特征被误判 | 见 [杀毒软件误报](#8-杀毒软件误报) |
| 签到成功但游戏里没奖励 | 需手动领取 | 在游戏内领取 |

## 1. 通知不弹出

按顺序排查，**不要跳步**。

### 第 1 步：主程序自带测试

右键托盘图标 → **「测试通知」**。

- **测试通知能弹出** → 程序侧正常，问题在具体签到流程。看日志确认签到是否真的执行了。
- **测试通知也不弹** → 系统层面问题，继续第 2 步。

### 第 2 步：检查系统通知设置

`设置` → `系统` → `通知和操作`：

1. 确认顶部 **「通知」总开关**是打开的
2. 向下滚动找到 **「绝区零自动签到」**，确认开关是打开的
3. 展开它，确认 **「显示通知横幅」** 已勾选

### 第 3 步：关闭专注助手 / 勿扰模式

`设置` → `系统` → `专注助手`（Windows 11 里叫「专注」）：

- 确认当前不是「仅优先通知」或「仅闹钟」模式
- 确认没有设置自动开启规则（比如全屏时开启）

开启专注助手时，通知会被**静默投递到通知中心但不弹横幅**，很容易误以为程序没工作。

### 第 4 步：检查是否被降级

程序在 Toast 发送失败时会**自动降级为托盘气泡提示**。看托盘图标附近有没有气泡，以及日志里有没有：

```
Toast 发送失败，降级为托盘气泡提示
```

### 第 5 步：检查快捷方式

自定义 AUMID 的 Toast 需要一个带该 AUMID 的开始菜单快捷方式。程序启动时会自动创建：

```
%APPDATA%\Microsoft\Windows\Start Menu\Programs\绝区零自动签到.lnk
```

若该文件缺失且日志中有「创建快捷方式失败」，可能是权限问题。手动处理：把 `ZzzAutoSign.exe` 的快捷方式复制到上述目录，右键 → 属性 → 在「目标」后加上 ` --autostart`。

## 2. 托盘没有图标

### 可能在隐藏区域

点托盘区域的 **向上箭头 `^`**，看是否被折叠。可以拖出来固定。

### 确认进程是否在跑

打开任务管理器，找 `ZzzAutoSign.exe`。

- **找不到** → 程序没启动或已崩溃。手动运行一次，观察是否有报错弹窗。
- **在运行但没图标** → 可能是 explorer.exe 重启导致托盘图标丢失。退出程序重新启动即可。

### 检查是否已有实例

程序是**单实例**的。如果已有一个实例在跑，第二个实例会静默退出。检查任务管理器里是否已有进程。

## 3. 进程监听启动失败

**报错**：「进程监听启动失败，请以管理员身份运行本程序」

**原因**：WMI 的进程事件订阅（`__InstanceCreationEvent`）需要管理员权限。

**处置**：

1. 右键 `ZzzAutoSign.exe` → 以管理员身份运行
2. 勾选「开机自启」时，程序会创建**计划任务**（`/RL HIGHEST`）来避免每次开机弹 UAC

**验证是否生效**：看日志，应该有：

```
WMI 进程监听已启动，目标：zenlesszonezero.exe（管理员=True）
```

### 管理员运行了还是失败

检查 WMI 服务：

```powershell
Get-Service Winmgmt | Select-Object Status, StartType
```

`Status` 应为 `Running`。若已停止：

```powershell
Start-Service Winmgmt
```

## 4. 签到没有被触发

### 检查目标进程名

程序默认匹配 `zenlesszonezero.exe`（不区分大小写）。确认游戏进程的实际名称：

```powershell
Get-Process | Where-Object { $_.Name -like "*zenless*" } | Select-Object Name, Path
```

如果实际名称不同（比如某启动器用了别的名字），在「设置」里改，或直接改 `settings.json` 的 `targetProcessName` 字段。

### 检查每日闸门状态

打开「设置」，看底部的状态行：

```
上次成功：2026-09-16　今日尝试：1 次　最近结果：成功 1 个角色
```

- **上次成功是今天** → 今天已经签过了，这是**预期行为**
- **今日尝试已到上限** → 当天不再自动重试。可在设置里调大上限，或点「重置今日」

### 日志里的判断依据

```
跳过签到：今天已完成签到
```

看到这行说明闸门工作正常，程序**故意**没有发起请求。

## 5. 凭证相关错误

### 「Driver not found: …\.playwright\node\win32_x64\node.exe」

报错长这样：

```
失败: Driver not found: C:\Users\<你>\.playwright\node\win32_x64\node.exe
```

**原因**：`CredentialGrabber.exe` 依赖 Playwright 的 node 驱动，它必须和 exe 放在
**同一个目录**下的 `.playwright\` 文件夹里。驱动不在，工具启动就会失败。

少见的情况下，这是程序打包出错（`v1.0.0` 的发布包就踩过：单文件发布会把这个文件
悄悄丢掉）。**更常见的是解压时只拿走了 exe**。

**处置**：确认 exe 旁边有这个结构（缺一不可）：

```
你解压的目录\
├─ CredentialGrabber.exe
├─ install-browser.cmd        （可选，用于下载内置浏览器内核）
└─ .playwright\
   ├─ node\win32_x64\node.exe
   └─ package\...
```

- 若是手动只复制了 exe：重新**整个文件夹**一起解压。
- 若目录结构确实完整却仍报错：说明拿到的是打包有问题的版本，
  升级到 `v1.0.1` 或更高版本。
- GitHub 的 Release 页可以直接下载 zip，解压后**不要单独移动 exe**。

### 「playwright.ps1 报找不到 Microsoft.Playwright.dll」

在 PowerShell 里执行 `.\playwright.ps1 install chromium` 会得到：

```
使用“1”个参数调用“ReadAllBytes”时发生异常:“未能找到文件
“C:\Users\<你>\Downloads\CredentialGrabber-win-x64\Microsoft.Playwright.dll”。”
找不到类型 [Microsoft.Playwright.Program]。
```

**原因**：`playwright.ps1` 是 Playwright 官方 NuGet 包自带的脚本，第 6 行要
`[Reflection.Assembly]::Load(ReadAllBytes("Microsoft.Playwright.dll"))`。
而本工具是**单文件发布**——那个 dll 已经打进 `CredentialGrabber.exe`，
磁盘上不会留副本。所以这个脚本在本工具的发布形态下**永远不可能成功**，
它留在包里纯属官方包的默认行为，不是给你用的。

**处置：不用管它，直接跳过。**

- 本仓库已从发布产物中移除 `playwright.ps1`，改用 `install-browser.cmd`。
- 手里若是 `v1.0.1` 或更早的包，看到这个脚本直接忽略，它不影响主程序。

### 需要安装浏览器内核时

**绝大多数情况不需要。** 工具的浏览器选择顺序是：

1. 系统安装的 **Google Chrome**
2. 系统安装的 **Microsoft Edge**（Windows 自带）
3. 内置 Chromium 内核（需另外下载）

只要 1 或 2 有一个在，就不会碰内置内核。启动时日志会写明用的是哪个。

只有 Chrome 和 Edge 都不可用时才需要下载，此时**双击**工具目录下的
`install-browser.cmd`。想先看它要做什么，可以在命令行执行
`install-browser.cmd --dry-run`。内核约 170 MB，下载到
`%USERPROFILE%\AppData\Local\ms-playwright`。

若下载总是失败（网络/代理问题），退而求其次：装一个 Chrome 或 Edge，
或者改用 [凭证获取指南](凭证获取指南.md) 里的**方式 B（F12 控制台脚本）**。


### 「未配置登录凭证，请先运行凭证提取工具」

`credential.bin` 不存在。运行 `CredentialGrabber.exe` 提取凭证。

### 「登录凭证已失效」

`cookie_token` 过期（约 1 天）。

**如果配置了 stoken**，程序会自动刷新，日志里会出现：

```
凭证失效，尝试用 stoken 刷新 cookie_token
已用 stoken 成功换取新的 cookie_token
```

**如果 stoken 也过期**，日志里会出现：

```
没有配置 stoken，无法自动刷新凭证
```

或

```
用 stoken 换取 cookie_token 失败
```

**处置**：重新运行 `CredentialGrabber.exe` 提取一次。

### 「v2 形态的 stoken 需要 mid 参数」

你的 stoken 是 `v2_` 前缀的新形态，必须同时提供 `mid`。

- 用方式 A（浏览器登录）重新提取，通常会自动带上 `mid`
- 或用方式 B，脚本会一并导出 `mid`
- 也可手动从浏览器 F12 → Application → Cookies 里找 `account_mid_v2` 或 `ltmid_v2`

### 「无法解密凭证」

`credential.bin` 由 DPAPI 以**当前 Windows 用户**为作用域加密。

- 换 Windows 用户 → 读不出来，需在新用户下重新提取
- 换电脑 → 同上
- 用户配置文件损坏 → 同上

**处置**：重新提取凭证。

## 6. 签名相关错误（retcode = -1）

**这是最需要注意的一类错误。**

**原因**：DS 签名必须与 salt / `x-rpc-app_version` / `x-rpc-client_type` 整体配对。米哈游升级客户端后可能更换 salt。

### 处置步骤

**第 1 步：切换签名模式**

程序已经在遇到 `-1` 时**自动尝试切换**签名模式（WebDs1 → AppDs1 → X6Ds2）。日志里会看到：

```
签名无效（当前 WebDs1），切换为 AppDs1 重试
```

若自动切换都失败，手动在「设置 → 签名模式」里逐个试。

**第 2 步：更新 endpoints.json**

自己抓包获取当前 salt：

1. Chrome 登录米游社，`F12` → `Network`
2. 在游戏内或网页完成一次签到
3. 找到发往 `act-nap-api.mihoyo.com/event/luna/zzz/sign` 的请求
4. 查看请求头的 `DS` 与 `x-rpc-app_version`
5. 按 [接口说明](接口说明.md) 第 4 节的算法反推 salt
6. 写入 `%LOCALAPPDATA%\ZzzAutoSign\endpoints.json`：

```json
{
  "saltWeb": "推导出的值",
  "appVersion": "抓到的版本号"
}
```

**不需要重新下载程序**，重启后生效。

**第 3 步：检查系统时间**

时间戳偏差超过约 5 分钟也会导致签名失败。确认 Windows 时间已同步：

```powershell
w32tm /resync
```

## 7. 风控与限流

### 「触发了米游社风险校验（需要验证码）」（retcode = 1034）

米游社检测到异常行为，要求人机验证。

**处置**：

1. 打开米游社 App 或网页，**手动完成一次签到**
2. 之后通常会自动恢复

**程序的行为**：**不会重试**这类错误。重试只会加重风控，并可能导致账号被临时限制。

### 「请求过于频繁，已被限流」（HTTP 429）

程序会按 5s → 15s → 45s 的退避序列自动重试，最多 3 次。

若频繁遇到：

- 减少手动触发「立即签到」的次数
- 确认没有同时运行多个同类工具
- 检查是否在多台设备上同时使用

## 8. 杀毒软件误报

**原因**：程序同时具备多个容易被启发式规则误判的特征：

- 单文件自解压（`PublishSingleFile` 会在临时目录释放依赖）
- 写入注册表 Run 键 / 创建计划任务
- 订阅 WMI 进程事件
- 发起带签名参数的 HTTPS 请求

**处置**：

1. 把程序目录加入杀毒软件的白名单/排除项
2. 源码完全公开，可自行审计后自行编译
3. 若不放心，可只在需要时手动运行，不勾选开机自启

## 9. 其他

### 程序占用多少资源

- 常驻时几乎不占 CPU（WMI 是事件驱动，不轮询）
- 内存约 50–80 MB（.NET 运行时开销）
- 每天只在实际触发时发起几次网络请求

### 换电脑怎么迁移

1. 在新电脑上安装并提取凭证（凭证无法迁移，因为 DPAPI 与用户/机器绑定）
2. 或者把 `settings.json` 复制过去（非敏感配置），凭证重新提取

### 卸载

1. 托盘菜单 → 退出
2. 取消勾选「开机自启」（会清除计划任务与注册表项）
3. 删除程序目录
4. 删除 `%LOCALAPPDATA%\ZzzAutoSign`（含凭证与日志）
5. 删除开始菜单快捷方式 `%APPDATA%\Microsoft\Windows\Start Menu\Programs\绝区零自动签到.lnk`

### 日志里有 `abcd***wxyz` 这种内容

这是**有意的脱敏**。日志中的 Cookie、stoken、mid 等凭证字段会被裁剪成「前 4 位 + `***` + 后 4 位」，避免明文凭证泄露。

## 还是解决不了

收集以下信息再反馈：

1. **日志文件**：`%LOCALAPPDATA%\ZzzAutoSign\logs\` 下当天的日志
2. **程序版本**：设置窗口标题 或 exe 文件属性
3. **具体现象**：什么时候、做了什么操作、看到什么提示
4. **接口返回码**：若通知里带了 `retcode=xxx`，一并提供

> 分享日志前请自行确认内容，程序虽已脱敏，但日志里仍可能包含你的 UID 等账号标识。
