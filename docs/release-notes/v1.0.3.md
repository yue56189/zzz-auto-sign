**没有功能改动，全部是发布产物本身的修复。** 建议升级——下过的包里有两处看不见的问题。

## 修了什么

### 1. `SHA256SUMS.txt` 的行尾

原先这个文件是用 Windows 的 `Set-Content -Encoding utf8` 写出来的，会带上
**CRLF 行尾**（在 PowerShell 5.1 下还会多一个 UTF-8 BOM）。

后果：在 Git Bash / WSL 里执行最常见的校验命令

```bash
sha256sum -c SHA256SUMS.txt
```

会得到一堆 `FAILED open or read`，报错里能看到文件名后面跟着一个 `\r`——
标准工具把回车符当成了文件名的一部分。

**摘要其实全对，文件本身也没坏**，但看起来就像附件损坏了。本版改成 LF 且不带 BOM，
上面这条命令现在可以直接跑通。

### 2. 许可证

仓库补上了 **MIT 许可证**，同时把许可文本放进发布包：

| 位置 | 内容 |
|---|---|
| 仓库根目录 `LICENSE` | MIT 全文，版权署名 `yue56189` |
| 两个 zip 包内 `LICENSE` | 与仓库原件逐字节一致 |
| `README.md` 「许可证」一节 | 许可证说明 + 随包第三方组件清单 |
| 两个 exe 的版本信息 | `Copyright (c) 2026 yue56189` |

MIT 要求在分发副本时一并给出许可与版权声明。发布流程只打包 `publish/` 目录，
而 `LICENSE` 在仓库根目录——它不会自己进 zip，所以之前两个包都是
「只有二进制、没有许可文本」的状态。

随包分发的 Playwright node 驱动是 Apache-2.0，它自带的许可文本位于包内
`.playwright\node\LICENSE` 与 `.playwright\package\LICENSE`，未做改动。

### 3. 新增的发布断言

CI 里加了两条硬断言，防止上面这类问题再次静默溜进发布包：

- `.playwright\node\` 下**只允许存在 `win32_x64`**（防误打 mac/linux 的 node，会多出 388 MB）
- 两个包的 `publish/` 目录里**必须有 `LICENSE`**，且内容确实是 MIT

## 下载

| 文件 | 用途 |
|---|---|
| `ZzzAutoSign-win-x64.zip` | 主程序：托盘、定时签到、桌面通知 |
| `CredentialGrabber-win-x64.zip` | 登录凭证提取工具 |
| `SHA256SUMS.txt` | 上述两个压缩包的 SHA256 校验和（本版起为 LF，无 BOM） |

自包含单文件发布，**无需另外安装 .NET 运行时**。仅支持 Windows x64。

> **解压整个压缩包，不要只把 exe 拿出来。**
> `CredentialGrabber.exe` 依赖同目录下的 `.playwright\` 文件夹，少了它就报
> `Driver not found`。详见 [排障手册](https://github.com/yue56189/zzz-auto-sign/blob/main/docs/排障手册.md)。

校验下载（PowerShell）：

```powershell
Get-FileHash .\CredentialGrabber-win-x64.zip -Algorithm SHA256
# 与 SHA256SUMS.txt 中的值比对
```

校验下载（Git Bash / WSL）——本版起可直接使用：

```bash
sha256sum -c SHA256SUMS.txt
```

## 已知限制

- **签名依赖 salt**：米哈游接口的 DS 签名与 `x-rpc-app_version` / salt 强耦合，
  官方更新客户端后可能失效，届时需重新抓取 `endpoints.json`（见 README 与排障手册）。
- **真机行为尚未完整验证**：托盘图标、Toast 通知、WMI 进程监听等需要在有账号的
  Windows 机器上实际跑一遍，核对清单见
  [`docs/实施与验证记录.md`](https://github.com/yue56189/zzz-auto-sign/blob/main/docs/实施与验证记录.md)。
