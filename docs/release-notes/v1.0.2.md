修复发布包里一个**注定报错**的脚本，并统一构建目标框架。**建议所有用户升级。**

## 修了什么

### 1. 从发布包中移除 `playwright.ps1`

在解压目录里执行 `.\playwright.ps1 install chromium` 会得到：

```
找不到文件 ...\Microsoft.Playwright.dll
找不到类型 [Microsoft.Playwright.Program]
```

这个脚本来自 Playwright 官方 NuGet 包，它的逻辑是
`[Reflection.Assembly]::Load([IO.File]::ReadAllBytes("Microsoft.Playwright.dll"))`，
然后反射调用 `[Microsoft.Playwright.Program]::Main($args)`——**它需要磁盘上真的有一个
`Microsoft.Playwright.dll`**。

而本项目用的是单文件自包含发布，那个 dll 早被打进 exe 里、磁盘上根本不存在。
所以这个脚本在本项目的发布形态下**永远不可能成功**，留在目录里只有一个作用：
把用户引到一条死路上去。

本版把它从产物中彻底摘掉（`DropBrokenPlaywrightScript`），
改由 `install-browser.cmd` 承担同样职责——直接调用随包的 node 驱动执行
`package\cli.js install chromium`，不依赖任何托管 dll，单文件模式下可用。

> **提示**：如果你本机已装 Edge 或 Chrome，通常**根本不需要下载内核**。
> 工具会依次尝试 msedge → chrome → 内置 chromium，实测 Edge 可直接驱动。

### 2. `CredentialGrabber` 的目标框架补上 Windows 平台版本

由 `net8.0-windows` 改为 `net8.0-windows10.0.18362.0`，与主程序、测试项目一致。

`net8.0-windows` 这种简写会把平台版本默认为 7.0，NuGet 会据此选中包内较老的资产
（历史上曾解析到 `lib/net5.0` 的精简版，缺 Windows 桌面 API），而且**不出警告、只在
用到某个成员时才报「类型不存在」**。本版把三处 TFM 拉到同一平台版本，消除这个隐患。

## 下载

| 文件 | 用途 |
|---|---|
| `ZzzAutoSign-win-x64.zip` | 主程序：托盘、定时签到、桌面通知 |
| `CredentialGrabber-win-x64.zip` | 登录凭证提取工具（本版移除 `playwright.ps1` 的就是它） |
| `SHA256SUMS.txt` | 上述两个压缩包的 SHA256 校验和 |

自包含单文件发布，**无需另外安装 .NET 运行时**。仅支持 Windows x64。
附件列表里可以看到每个压缩包的实际体积。

> **解压整个压缩包，不要只把 exe 拿出来。**
> `CredentialGrabber.exe` 依赖同目录下的 `.playwright\` 文件夹，少了它就报
> `Driver not found`。详见 [排障手册](https://github.com/yue56189/zzz-auto-sign/blob/main/docs/排障手册.md)。

校验下载：

```powershell
Get-FileHash .\CredentialGrabber-win-x64.zip -Algorithm SHA256
# 与 SHA256SUMS.txt 中的值比对
```

## 已知限制

- **签名依赖 salt**：米哈游接口的 DS 签名与 `x-rpc-app_version` / salt 强耦合，
  官方更新客户端后可能失效，届时需重新抓取 `endpoints.json`（见 README 与排障手册）。
- **真机行为尚未完整验证**：托盘图标、Toast 通知、WMI 进程监听等需要在有账号的
  Windows 机器上实际跑一遍，核对清单见
  [`docs/实施与验证记录.md`](https://github.com/yue56189/zzz-auto-sign/blob/main/docs/实施与验证记录.md)。
